# Zapier App Directory

- Public listing = publishing a public integration from the Zapier Developer Platform (Platform UI or Platform CLI). All integrations start private.
- Steps: plan workflows, build triggers/actions/searches with auth, test in the Zap editor, then Integration Home, Publish, fill the form, **Submit for Review**. Version shows Pending while the app stays Private.
- Review: a Zapier developer responds in "1 week or less" with outstanding requirements. Reviewers can reject or remove integrations; many near-identical integrations slow review.
- Requirements (integration publishing requirements page): fully launched to the public (not invite-only or beta); each trigger, action and search tested with a turned-on Zap that has at least one successful run; a non-expiring test account for integration-testing@zapier.com; at least one admin team member with a qualifying email domain.
- After approval: Beta status with a Beta tag in the directory for 90 days, then public. Early exit once one signup is detected from the Zapier embed.
- Active-user thresholds: not stated in the official docs read. Third-party posts cite figures (3 live-Zap users, 50 active users, 10 Zap templates); treat as unverified and confirm with PublishBot.
- Free: "There are no fees for publishing an integration."
- Listing pages link to the product site with `rel="nofollow noopener noreferrer"`; robots meta is `all` (3 samples).
- Zapier MCP: no separate MCP/AI-actions directory submission was found. Zapier MCP exposes actions of published integrations to AI clients (tool calls cost 2 tasks), so a published integration is the route; a dedicated listing process is not established.
- Research only; no account created, nothing submitted.
